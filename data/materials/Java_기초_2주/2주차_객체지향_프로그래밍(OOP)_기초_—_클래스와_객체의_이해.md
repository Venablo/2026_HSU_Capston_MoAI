### 📌 이번 주차 전체 지도
1주차에서 Java의 기본적인 변수, 연산자, 제어문을 학습했다면, 2주차는 Java의 정수인 객체지향 프로그래밍(OOP, Object-Oriented Programming)의 기초를 다룹니다. 절차지향적 코딩에서 벗어나 실생활의 사물을 모델링하는 '클래스'와 이를 실체화한 '인스턴스'의 개념을 익히고, 생성자, 메서드, 상속, 캡슐화까지 학습합니다. 이 학습 순서는 먼저 객체의 기본 설계도를 이해하고, 객체의 상태와 행위를 정의한 뒤, 객체 간의 관계를 맺는 방식으로 구성됩니다.

### 1️⃣ 클래스(Class)와 인스턴스(Instance)
- 정의: 클래스는 객체를 만들기 위한 설계도이며, 인스턴스는 설계도를 바탕으로 메모리에 생성된 실제 구현체입니다.
- 원리: 클래스는 속성(필드)과 기능(메서드)을 정의합니다. 'new' 키워드를 사용하여 메모리 힙(Heap) 영역에 객체를 할당합니다.
- 예시: '붕어빵 틀'(클래스)과 '붕어빵'(인스턴스).
- 주의사항: 클래스는 추상적인 정의일 뿐 메모리를 점유하지 않으며, 인스턴스만이 데이터를 가질 수 있습니다.
- 시험 포인트: 객체 생성 시 new 연산자의 역할(참조값 반환)과 멤버 접근법(dot 연산자).

### 2️⃣ 생성자(Constructor)
- 정의: 객체가 생성될 때 호출되는 특별한 메서드로, 멤버 변수를 초기화하는 역할을 합니다.
- 원리: 클래스명과 동일한 이름이며 반환형이 없습니다. 생성자를 정의하지 않으면 컴파일러가 기본 생성자를 삽입합니다.
- 예시: Student(String name) { this.name = name; }
- 주의사항: 일반 메서드와 달리 반환 타입(void 포함)을 명시하지 않습니다.
- 시험 포인트: 기본 생성자 생성 규칙과 매개변수가 있는 생성자 호출 시의 오버로딩.

### 3️⃣ 메서드 오버로딩(Method Overloading)
- 정의: 동일한 이름의 메서드를 매개변수의 타입이나 개수를 다르게 하여 여러 개 정의하는 것.
- 원리: 컴파일러가 매개변수의 시그니처(Signature)를 확인하여 어떤 메서드를 실행할지 결정합니다.
- 예시: println(int), println(String) 등.
- 주의사항: 반환 타입만 다른 경우는 오버로딩으로 인정되지 않습니다.
- 시험 포인트: 오버로딩 성립 조건(매개변수 리스트 차이).

### 4️⃣ 캡슐화(Encapsulation)
- 정의: 객체의 내부 데이터를 외부에서 함부로 접근하지 못하도록 보호하는 개념.
- 원리: 접근 제어자(private, public)를 사용하여 필드를 숨기고, Getter/Setter를 통해 접근을 제어합니다.
- 예시: 은행 잔액(balance) 필드를 private으로 설정 후 입금 메서드로만 변경 가능하게 함.
- 주의사항: 무조건적인 public은 데이터 오염의 원인이 됩니다.
- 시험 포인트: private 변수에 접근하기 위한 public Getter/Setter의 역할.

### 5️⃣ 상속(Inheritance)
- 정의: 부모 클래스의 기능을 자식 클래스가 물려받아 재사용하는 것.
- 원리: 'extends' 키워드를 사용하며, 코드의 중복을 줄이고 다형성을 확보합니다.
- 예시: '동물' 클래스를 상속받은 '강아지' 클래스.
- 주의사항: Java는 단일 상속만 지원합니다.
- 시험 포인트: super 키워드의 사용과 부모 생성자 호출 여부.

### 6️⃣ 다형성(Polymorphism)
- 정의: 하나의 타입(부모)이 여러 자식 객체를 가리킬 수 있는 성질.
- 원리: 부모 타입의 참조변수로 자식 인스턴스를 참조하여 상황에 맞는 메서드를 실행.
- 예시: Animal myPet = new Dog(); myPet.sound();
- 주의사항: 참조변수 타입에 따라 호출 가능한 메서드가 결정됩니다.
- 시험 포인트: 업캐스팅(Upcasting)과 메서드 오버라이딩(Overriding)의 이해.

### 📊 비교 정리표 1: 클래스 vs 객체
| 구분 | 클래스(Class) | 객체(Object/Instance) |
| :--- | :--- | :--- |
| 정의 | 설계도(틀) | 실체(붕어빵) |
| 메모리 | 로드 시점 | new 연산 시점 |
| 역할 | 모델링/규격 | 상태 저장/연산 |

### 📊 비교 정리표 2: 일반 메서드 vs 생성자
| 구분 | 일반 메서드 | 생성자 |
| :--- | :--- | :--- |
| 목적 | 특정 행위 수행 | 인스턴스 초기화 |
| 이름 | 임의 지정 가능 | 클래스명과 동일 |
| 반환타입 | 필수 | 없음(void도 불가) |

## 연습 퀴즈

1. Java에서 생성자(Constructor)에 대한 설명으로 틀린 것은?
   A. 생성자는 클래스 이름과 동일해야 한다.
   B. 반환 타입(return type)을 명시적으로 선언해야 한다.
   C. 객체가 생성될 때 자동으로 호출된다.
   D. 매개변수를 다르게 하여 여러 개 정의할 수 있다.
   정답: B
   관련 키워드: 생성자
   해설: 생성자는 객체 초기화를 위한 특별한 메서드로, 반환 타입(void 포함)을 절대 명시하지 않습니다. A, C, D는 생성자의 올바른 특징입니다.

2. 캡슐화(Encapsulation)를 구현하는 주된 목적은 무엇인가?
   A. 코드의 양을 최대한 줄이기 위해
   B. 상속 관계를 복잡하게 만들기 위해
   C. 데이터의 무결성을 보호하고 외부 접근을 통제하기 위해
   D. 메서드 실행 속도를 향상시키기 위해
   정답: C
   관련 키워드: 캡슐화
   해설: 캡슐화는 내부 데이터(필드)를 외부로부터 숨기고, public한 메서드를 통해 안전하게 데이터를 수정하도록 하여 무결성을 보장하는 기술입니다.

3. 다음 중 메서드 오버로딩(Overloading)의 조건으로 적절한 것은?
   A. 메서드의 이름은 같지만 매개변수의 개수나 타입이 달라야 한다.
   B. 반환 타입만 다르면 이름이 같아도 오버로딩이다.
   C. 접근 제어자가 다르면 이름이 같아도 오버로딩이다.
   D. 메서드 내의 로직이 완전히 일치해야 한다.
   정답: A
   관련 키워드: 메서드 오버로딩
   해설: 오버로딩은 메서드 이름이 같을 때 매개변수의 리스트(타입, 개수, 순서)가 달라야 성립합니다. 반환 타입이나 접근 제어자는 관계없습니다.

4. 객체지향에서 '상속'을 사용할 때의 이점으로 옳지 않은 것은?
   A. 코드의 재사용성을 높인다.
   B. 클래스 간의 계층 구조를 형성할 수 있다.
   C. 여러 부모 클래스를 동시에 상속받아 다중 상속을 지원한다.
   D. 유지보수가 용이해진다.
   정답: C
   관련 키워드: 상속
   해설: Java는 다이아몬드 문제 등을 방지하기 위해 클래스 간의 다중 상속을 지원하지 않으며, 단일 상속만 가능합니다.

5. 부모 타입의 참조변수로 자식 인스턴스를 참조하여 실행하는 개념은?
   A. 캡슐화
   B. 다형성
   C. 추상화
   D. 메서드 오버로딩
   정답: B
   관련 키워드: 다형성
   해설: 다형성은 같은 부모 클래스 타입을 사용하여 여러 가지 형태의 자식 객체를 처리할 수 있는 OOP의 핵심 원리입니다.
