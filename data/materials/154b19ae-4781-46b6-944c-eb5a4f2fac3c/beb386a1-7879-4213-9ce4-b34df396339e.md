## 마크다운 학습 자료

### 📌 이번 주차 전체 지도
이번 주차는 스프링 프레임워크 생태계에 입문하는 첫 단계로, 기존 스프링의 복잡한 설정 지옥을 해결하기 위해 등장한 스프링부트(Spring Boot)의 탄생 배경을 학습합니다. 이후 IntelliJ 환경 설정과 Spring Initializr를 활용한 프로젝트 생성법을 익히고, 핵심 구성 요소인 Auto Configuration과 Embedded Tomcat의 동작 원리를 파악하여 성공적으로 Hello World를 실행하는 것이 목표입니다. 이 과정은 차주에 배울 IoC/DI(의존성 주입) 및 컨테이너 관리의 기초 체력이 됩니다.

### 1️⃣ 핵심 개념 6개

1. **Spring Boot Starter(스타터):** 의존성 집합체입니다. 특정 기능(예: Web, JPA)을 위한 라이브러리를 하나하나 찾는 대신, 미리 정의된 의존성 묶음을 사용하여 프로젝트 구성을 간소화합니다. 예: spring-boot-starter-web. 주의: 너무 많은 스타터를 추가하면 빌드 속도가 저하됩니다. 시험 포인트: '의존성 관리의 효율화' 키워드.

2. **Auto Configuration(자동 설정):** 스프링부트의 핵심 마법입니다. 클래스패스 내에 특정 라이브러리가 존재하면, 해당 라이브러리를 사용하기 위한 기본 설정(Bean)을 자동으로 등록합니다. 주의: 자동 설정을 무조건 의존하기보다 `@SpringBootApplication`의 어노테이션 이해가 선행되어야 합니다.

3. **Dependency Management(의존성 관리):** Gradle이나 Maven에서 라이브러리 버전 호환성을 스프링부트 버전에 맞춰 자동으로 관리합니다. 개별 라이브러리의 버전을 신경 쓰지 않아도 됩니다.

4. **Application.properties/yml:** 설정을 관리하는 중심 파일입니다. 서버 포트(server.port), DB 연결 정보 등을 관리합니다. 주의: properties와 yml을 동시에 사용하지 않는 것을 권장합니다.

5. **Embedded Tomcat(내장 톰캣):** 별도의 서버 설치 없이 애플리케이션 자체가 서버를 포함하는 구조입니다. JAR 파일 하나만으로 서비스가 가능합니다.

6. **@SpringBootApplication:** @Configuration, @EnableAutoConfiguration, @ComponentScan 세 가지 어노테이션을 결합한 어노테이션으로, 스프링부트의 시작점(Entry Point)입니다.

### 📊 비교 정리표 2개

| 비교 항목 | 기존 스프링 (Spring Framework) | 스프링부트 (Spring Boot) |
| :--- | :--- | :--- |
| 설정 방식 | 복잡한 XML 또는 Java 설정 직접 작성 | 어노테이션 기반 자동 설정 (Auto Configuration) |
| 서버 환경 | 외부 톰캣(Tomcat) 컨테이너 설치 필요 | 내장 톰캣(Embedded Tomcat) 포함 |
| 의존성 관리 | 개별 라이브러리 버전 일일이 정의 | 스타터(Starter)를 통해 버전 관리 자동화 |

| 파일 구분 | Application.properties | Application.yml |
| :--- | :--- | :--- |
| 가독성 | 낮음 (계층 구조 표현 불가) | 높음 (들여쓰기 기반 계층 구조) |
| 유연성 | 단순 키-값 형태 | 복잡한 객체 설정에 용이 |

### 🧪 실전 시나리오 3개
1. **서버 포트 변경:** 기본 8080 포트가 이미 점유된 상황, `application.properties`에서 `server.port=9090`을 추가하여 충돌 해결.
2. **스타터 추가:** 게시판 개발을 위해 웹 기능을 추가해야 함. `build.gradle`의 `dependencies`에 `implementation 'org.springframework.boot:spring-boot-starter-web'` 추가 후 Sync 수행.
3. **자동 설정 확인:** 스프링부트가 실행될 때 적용된 자동 설정 목록을 보고 싶다면 `debug=true` 설정을 추가하여 로그 확인.

### 🚨 자주 하는 실수 TOP 6
1. JDK 버전과 프로젝트 설정 버전 불일치(LTS 버전 권장).
2. Gradle Sync를 누르지 않고 라이브러리가 없다고 당황함.
3. `@SpringBootApplication`이 포함된 메인 클래스가 다른 패키지 최상단에 위치하지 않음.
4. Application.properties 내의 오타로 인한 설정 미적용.
5. 포트 번호 충돌 시 에러 메시지 무시.
6. 빌드 도구(Gradle vs Maven)를 잘못 선택하여 의존성 추가 방식 혼동.

### 💡 시험 포인트 & 암기 장치
* 암기: **'사(Starter)·자(Auto)·내(Embedded)'** (스프링부트 3대장).
* 포인트: 자동 설정은 무조건 수행되는 것이 아니라, 클래스패스에 라이브러리가 있을 때만 동작함.

## 연습 퀴즈

1. 스프링부트의 핵심 기능인 'Auto Configuration'에 대한 설명으로 올바른 것은?
   A. 모든 설정 파일을 사용자가 직접 XML로 작성해야 한다.
   B. 클래스패스의 의존성을 기반으로 필요한 설정을 자동으로 등록한다.
   C. 자동으로 데이터베이스 테이블을 설계해준다.
   D. 스프링 프레임워크가 아닌 외부 라이브러리만 관리한다.
   정답: B
   관련 키워드: Auto Configuration
   해설: Auto Configuration은 클래스패스 내의 라이브러리들을 감지하여, 해당 라이브러리를 사용하기 위한 빈(Bean)들을 자동으로 구성해주는 스프링부트의 핵심 기능입니다.

2. 스프링부트에서 웹 애플리케이션을 배포할 때 가장 큰 장점은 무엇인가?
   A. 반드시 외부 톰캣 서버를 설치해야 한다.
   B. 내장 톰캣(Embedded Tomcat)을 사용하여 별도 설치 없이 실행 가능하다.
   C. HTTP 프로토콜을 사용하지 않아도 된다.
   D. 배포 파일 크기가 외부 톰캣 방식보다 훨씬 커진다.
   정답: B
   관련 키워드: Embedded Tomcat
   해설: 스프링부트는 내장 톰캣을 포함하고 있어, 애플리케이션 자체가 하나의 실행 가능한 JAR 파일로 완성되므로 별도의 서버 설치 과정이 필요 없습니다.

3. 다음 중 스프링부트 메인 클래스에 반드시 존재해야 하는 어노테이션은?
   A. @EnableAutoConfiguration
   B. @SpringBootApplication
   C. @Configuration
   D. @ComponentScan
   정답: B
   관련 키워드: @SpringBootApplication
   해설: @SpringBootApplication은 내부적으로 @Configuration, @EnableAutoConfiguration, @ComponentScan을 포함하고 있어 프로젝트의 설정 시작점으로 사용됩니다.

4. 프로젝트의 빌드 도구인 Gradle에서 의존성을 관리하는 가장 큰 이유는?
   A. 코딩 스타일을 검사하기 위해
   B. 라이브러리 버전 간의 호환성을 자동으로 관리하기 위해
   C. 데이터베이스를 자동으로 생성하기 위해
   D. 브라우저 엔진을 관리하기 위해
   정답: B
   관련 키워드: Dependency Management
   해설: 스프링부트는 '스타터'와 함께 의존성 관리 기능을 제공하여, 서로 호환되는 라이브러리 버전을 자동으로 맞춰주어 개발자가 버전 관리 부담을 줄여줍니다.

5. 설정 파일에서 서버 포트를 8080에서 9090으로 변경하는 속성은?
   A. spring.port=9090
   B. web.port=9090
   C. server.port=9090
   D. app.port=9090
   정답: C
   관련 키워드: Application.properties
   해설: 스프링부트에서 서버 관련 설정은 server 접두사를 사용하며, 포트 번호 변경은 server.port 프로퍼티를 통해 수행합니다.

## 주차 과제

제목: Hello World API 구현 및 설정 변경

IntelliJ에서 스프링부트 프로젝트를 생성하고, 웹 브라우저에서 'Hello World'를 출력하는 API를 작성한 후 서버 포트를 변경해 보세요.

[제출 체크리스트]
- Spring Initializr로 생성한 프로젝트 구조 스크린샷
- RestController를 이용한 Hello API 코드 작성
- application.properties에서 포트 변경(8080 -> 9090)
- 브라우저에서 변경된 포트로 접속 성공한 결과 캡처

[필수 키워드] Spring Initializr, RestController, application.properties, Gradle

[수행 단계]
1. 1. 프로젝트 생성(Web Starter 선택)
2. 2. 컨트롤러 클래스 작성(@RestController, @GetMapping)
3. 3. 설정 파일에서 포트 번호 수정 및 실행

[채점 기준] 정상적인 서버 구동 여부와 요구된 설정 파일 수정 여부를 기준으로 100점 만점 평가.
