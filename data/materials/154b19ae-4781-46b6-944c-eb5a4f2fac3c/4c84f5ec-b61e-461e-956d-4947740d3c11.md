### 📌 이번 주차 전체 지도
1주차에서 스프링 부트의 프로젝트 구조와 기본 실행 과정을 학습했다면, 2주차에는 스프링의 가장 강력한 무기인 'IoC(제어의 역전)'와 'DI(의존성 주입)'를 깊이 있게 다룹니다. 객체를 직접 생성하던 과거의 방식에서 벗어나, 스프링 컨테이너가 어떻게 객체의 생명주기를 제어하고 필요한 곳에 주입하는지를 학습합니다. 학습 순서는 [IoC 개념 이해] → [빈(Bean) 등록 방식] → [DI 구현 방법] → [생성자 주입의 중요성] 순으로 진행됩니다.

### 1️⃣ IoC (Inversion of Control, 제어의 역전)
- 정의: 프로그램의 제어권이 개발자에서 프레임워크(스프링 컨테이너)로 넘어가는 현상.
- 원리: 객체의 생성, 초기화, 소멸을 개발자가 직접 작성하지 않고 컨테이너에 위임함.
- 예시: new 연산자 대신 스프링이 미리 만든 객체를 가져다 사용하는 것.
- 주의사항: 모든 객체를 스프링이 관리하게 하면 오히려 복잡도가 증가할 수 있으므로 관리 대상을 적절히 선정해야 함.
- 시험 포인트: "누가 객체 생명주기를 관리하는가?"에 대한 답변으로 '스프링 컨테이너'를 명확히 해야 함.

### 2️⃣ DI (Dependency Injection, 의존성 주입)
- 정의: 객체가 필요로 하는 의존 객체를 외부에서 주입해주는 설계 패턴.
- 원리: 클래스 간의 결합도를 낮추어 변경에 유연한 코드 구현.
- 예시: OrderService가 MemberRepository에 의존할 때, 직접 생성하지 않고 생성자를 통해 외부에서 넘겨받음.
- 주의사항: 순환 참조(Circular Dependency)가 발생하지 않도록 설계에 유의.
- 시험 포인트: 결합도(Coupling)를 낮추어 유지보수성을 높인다는 점이 핵심.

### 3️⃣ Spring Bean (스프링 빈)
- 정의: 스프링 컨테이너에 의해 관리되는 자바 객체.
- 원리: @Bean이나 @Component 어노테이션을 통해 컨테이너에 등록.
- 예시: @Service, @Repository 등이 붙은 클래스는 스프링 빈으로 자동 등록됨.
- 주의사항: 스프링 빈은 기본적으로 싱글톤(Singleton) 스코프를 가짐.
- 시험 포인트: 컴포넌트 스캔(Component Scan) 범위 내에서 빈이 자동으로 등록되는 원리.

### 4️⃣ 생성자 주입 (Constructor Injection)
- 정의: 생성자를 통해 의존성을 주입하는 방식.
- 원리: 객체 생성 시점에 의존 관계가 완성되어 안정성이 높음.
- 예시: @RequiredArgsConstructor 어노테이션을 사용한 생성자 자동 생성.
- 주의사항: 필드 주입과 달리 final 키워드를 사용하여 불변성 보장 가능.
- 시험 포인트: 왜 필드 주입보다 생성자 주입이 권장되는지(테스트 용이성, 불변성).

### 5️⃣ 컴포넌트 스캔 (Component Scan)
- 정의: @Component 어노테이션이 붙은 클래스를 찾아 빈으로 등록하는 기능.
- 원리: @ComponentScan 설정에 따라 패키지를 탐색하여 자동으로 빈 등록.
- 예시: @SpringBootApplication 하위 패키지들은 기본적으로 스캔 대상.
- 주의사항: 너무 넓은 범위의 스캔은 초기 구동 시간을 지연시킴.
- 시험 포인트: 어노테이션을 통한 자동 설정과 수동 설정(@Configuration)의 차이.

### 6️⃣ 스프링 컨테이너 (Spring Container)
- 정의: 빈의 생성, 의존성 주입, 소멸을 관리하는 핵심 컨테이너.
- 원리: BeanFactory를 기반으로 하여 ApplicationContext가 실질적인 기능을 수행.
- 예시: 애플리케이션 실행 시 컨테이너가 초기화되며 모든 빈이 생성됨.
- 주의사항: 컨테이너가 무거워질 수 있으므로 성능 최적화 고려 필요.
- 시험 포인트: 컨테이너의 역할(객체 관리)을 이해하는지 확인.

## 연습 퀴즈

1. 스프링에서 의존성 주입(DI)을 사용하는 가장 주된 이유는 무엇인가요?
   A. 애플리케이션의 실행 속도를 높이기 위해
   B. 객체 간의 결합도를 낮추고 유지보수성을 높이기 위해
   C. 메모리 사용량을 최소화하기 위해
   D. 모든 객체를 자동으로 생성하기 위해
   정답: B
   관련 키워드: Dependency Injection
   해설: DI의 핵심은 의존 객체를 외부에서 주입받음으로써 클래스 간의 결합도를 낮추는 것입니다. 이를 통해 유연한 변경과 테스트가 가능해집니다.

2. 생성자 주입이 필드 주입보다 권장되는 이유로 옳지 않은 것은?
   A. 객체의 불변성을 보장할 수 있다.
   B. 테스트 코드 작성 시 모킹(Mocking)이 용이하다.
   C. 필드 주입보다 코드가 짧고 간결하다.
   D. 순환 참조를 컴파일 시점에 발견하기 쉽다.
   정답: C
   관련 키워드: 생성자 주입
   해설: 생성자 주입은 생성자 코드가 추가되므로 필드 주입보다 코드가 길어집니다. 하지만 불변성, 테스트 용이성, 순환 참조 방지 등 품질 측면에서 훨씬 우수합니다.

3. 다음 중 스프링 빈(Spring Bean)의 기본 스코프는 무엇인가요?
   A. Prototype
   B. Request
   C. Singleton
   D. Session
   정답: C
   관련 키워드: Spring Bean
   해설: 스프링 빈은 기본적으로 스프링 컨테이너당 하나의 인스턴스만 생성하여 공유하는 싱글톤(Singleton) 방식을 따릅니다.

4. 컴포넌트 스캔(Component Scan)이 자동으로 빈을 등록하는 대상이 아닌 것은?
   A. @Service
   B. @Repository
   C. @Controller
   D. @Configuration
   정답: D
   관련 키워드: Component Scan
   해설: @Configuration은 빈을 등록하는 설정 파일이며, 내부에 @Bean을 사용하여 빈을 정의합니다. 물론 @Configuration 클래스 자체도 @Component를 포함하지만, 일반적으로 @Service 등과 직접적인 빈 등록 대상 범주와는 구별됩니다.

5. IoC(제어의 역전)에 대한 설명으로 올바른 것은?
   A. 개발자가 모든 객체의 생성과 소멸을 직접 관리한다.
   B. 프레임워크가 프로그램의 흐름을 제어하고 객체를 관리한다.
   C. 외부 라이브러리 사용 시 반드시 필요한 개념이다.
   D. 데이터베이스 연결을 최적화하는 기술이다.
   정답: B
   관련 키워드: IoC
   해설: IoC는 기존에 개발자가 제어하던 객체의 생명주기 관리 권한을 프레임워크에게 넘기는 것을 의미합니다.
