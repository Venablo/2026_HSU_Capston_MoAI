### 1️⃣ JPA(Java Persistence API)의 이해
- 정의: 자바 객체와 관계형 데이터베이스(RDB) 간의 매핑을 관리하는 ORM(Object-Relational Mapping) 표준 기술입니다.
- 원리: 객체는 객체대로, DB 테이블은 테이블대로 설계하고, 중간에서 JPA가 이 둘을 매핑해줍니다.
- 예시: User 클래스를 만들고 @Entity를 붙이면 테이블과 자동 매핑됩니다.
- 주의사항: DB 방언(Dialect) 설정이 중요합니다.
- 시험 포인트: JPA는 인터페이스의 모음이며 실제 구현체는 하이버네이트(Hibernate)임을 기억하세요.

### 2️⃣ 엔티티(Entity) 매핑
- 정의: DB 테이블과 1:1로 대응되는 자바 클래스입니다.
- 원리: @Entity 어노테이션을 클래스에 붙이고, @Id로 기본키를 지정합니다.
- 예시: @Table(name = "members")와 같이 테이블명을 커스텀할 수 있습니다.
- 주의사항: 반드시 파라미터가 없는 기본 생성자(protected 이상)가 필요합니다.
- 시험 포인트: @Column 어노테이션으로 컬럼명, 길이, nullable 제약조건을 정의하는 방법을 숙지하세요.

### 3️⃣ 영속성 컨텍스트(Persistence Context)
- 정의: 엔티티를 영구히 저장하는 환경입니다.
- 원리: EntityManager가 엔티티를 관리하며, 변경 사항을 감지(Dirty Checking)합니다.
- 예시: save()를 호출하면 바로 DB에 가는 것이 아니라 1차 캐시에 저장됩니다.
- 주의사항: 엔티티 매니저 팩토리는 하나만 생성해서 공유합니다.
- 시험 포인트: 1차 캐시, 동일성 보장, 트랜잭션 쓰기 지연의 개념을 이해해야 합니다.

### 4️⃣ 리포지토리(Repository) 인터페이스
- 정의: 데이터 접근 계층을 위한 인터페이스입니다.
- 원리: JpaRepository를 상속받으면 CRUD 기능이 자동으로 제공됩니다.
- 예시: public interface MemberRepository extends JpaRepository<Member, Long> { }
- 주의사항: 인터페이스만 정의해도 스프링이 구현체를 자동으로 생성합니다.
- 시험 포인트: JpaRepository가 제공하는 save, findById, delete 등의 기본 메서드를 암기하세요.

### 5️⃣ 쿼리 메서드(Query Method)
- 정의: 메서드 이름만으로 JPQL 쿼리를 생성하는 기능입니다.
- 원리: findBy + 필드명 규칙을 사용합니다.
- 예시: findByName(String name)은 'SELECT * FROM member WHERE name = ?'을 실행합니다.
- 주의사항: 메서드 이름 규칙이 틀리면 컴파일 에러가 발생합니다.
- 시험 포인트: And, Or, Between 등 예약어 조합 능력이 핵심입니다.

### 6️⃣ 데이터베이스 연동 및 생명주기
- 정의: 비영속(new) -> 영속(managed) -> 준영속(detached) -> 삭제(removed) 단계입니다.
- 원리: 트랜잭션 범위 안에서 관리되며 commit 시점에 DB와 동기화됩니다.
- 예시: 데이터베이스 작업은 반드시 @Transactional 어노테이션과 함께 수행되어야 합니다.
- 주의사항: 트랜잭션이 종료되면 데이터가 반영되므로 예외 발생 시 롤백됩니다.
- 시험 포인트: 영속 상태의 엔티티가 변경되면 별도의 업데이트 메서드 없이도 DB에 반영됩니다.

### 📊 비교 정리표
| 항목 | JPA | 하이버네이트(Hibernate) |
|---|---|---|
| 성격 | 기술 표준(API) | 구현체(라이브러리) |
| 역할 | 명세 제공 | 실제 동작 구현 |
| 관계 | 인터페이스 | JPA를 구현한 실질적 엔진 |

| 항목 | 리포지토리(Repository) | 쿼리 메서드(Query Method) |
|---|---|---|
| 역할 | 데이터 접근 추상화 | 커스텀 쿼리 자동 생성 |
| 방식 | 상속을 통한 표준 메서드 사용 | 메서드 명 규칙 기반 쿼리 수행 |

### 🧪 실전 시나리오
1. 유저 회원가입: 컨트롤러에서 받은 DTO를 Entity로 변환 후 repository.save()를 호출하여 DB에 저장합니다.
2. 유저 정보 검색: id를 기반으로 findById()를 사용하여 Optional 처리를 통해 null 안정성을 확보합니다.
3. 비밀번호 변경: 엔티티를 조회한 후 setter로 변경하고 @Transactional 내에서 자동으로 변경 감지가 일어나 업데이트를 수행합니다.

### 🚨 자주 하는 실수 TOP 6
1. 기본 생성자 누락 (Entity는 기본 생성자 필수).
2. @Transactional 누락 (데이터 변경 시 예외 발생).
3. JpaRepository 제네릭 타입 실수 (첫 번째는 엔티티 클래스, 두 번째는 ID 타입).
4. 쿼리 메서드 오타 (findByNmae 처럼 오타 발생).
5. 연관관계 매핑 시 순환 참조.
6. 무조건적인 setter 사용 (엔티티 상태 관리를 어렵게 만듦).

## 연습 퀴즈

1. JPA와 하이버네이트의 관계에 대한 설명으로 옳은 것은?
   A. JPA는 라이브러리이고 하이버네이트는 명세이다.
   B. JPA는 자바 표준 명세이며 하이버네이트는 그 구현체 중 하나이다.
   C. 하이버네이트를 사용하려면 JPA를 사용할 수 없다.
   D. 두 기술은 서로 관련이 없는 독립적인 기술이다.
   정답: B
   관련 키워드: JPA
   해설: JPA는 인터페이스 기반의 명세(Specification)이고, 하이버네이트는 이를 실제로 동작하도록 구현한 프레임워크입니다.

2. 엔티티(Entity) 클래스를 설계할 때 반드시 필요한 것은?
   A. public 기본 생성자
   B. 모든 필드에 대한 setter
   C. 기본 생성자(protected 이상)
   D. 데이터베이스 연결 정보
   정답: C
   관련 키워드: Entity
   해설: JPA 스펙상 엔티티는 리플렉션을 위해 최소 protected 수준 이상의 파라미터가 없는 기본 생성자가 반드시 필요합니다.

3. 영속성 컨텍스트(Persistence Context)의 장점이 아닌 것은?
   A. 1차 캐시를 통한 조회 성능 향상
   B. 동일성 보장
   C. 트랜잭션 쓰기 지연
   D. 데이터베이스 연결 개수의 무제한 증가
   정답: D
   관련 키워드: Persistence Context
   해설: 영속성 컨텍스트는 효율적인 처리를 돕지만 DB 연결 개수를 무제한으로 늘려주는 기술은 아닙니다.

4. JpaRepository를 상속받은 인터페이스에서 '이름'으로 조회하는 쿼리 메서드 이름으로 옳은 것은?
   A. getName(String name)
   B. findBy(String name)
   C. findByName(String name)
   D. selectByName(String name)
   정답: C
   관련 키워드: Query Method
   해설: Spring Data JPA의 쿼리 메서드 명명 규칙은 findBy + 필드명 입니다.

5. 엔티티의 생명주기에서 영속 상태(Managed)를 설명하는 것으로 옳은 것은?
   A. DB에 저장되지 않고 객체만 생성된 상태
   B. 영속성 컨텍스트에 의해 관리되는 상태
   C. 영속성 컨텍스트에서 분리된 상태
   D. 데이터베이스에서 완전히 삭제된 상태
   정답: B
   관련 키워드: Persistence Context
   해설: 영속 상태란 EntityManager에 의해 관리되며, 트랜잭션 커밋 시점에 DB에 반영될 준비가 된 상태입니다.
