## 마크다운 학습 자료 — 8주차: 환경 설정과 프로파일 (Profiles)

### 📌 이번 주차 전체 지도
7주차까지 스프링 부트의 기본 구조와 Bean 관리, 데이터베이스 연결을 학습했다면, 8주차는 이러한 설정을 환경(개발/테스트/운영)에 따라 유연하게 분리하는 관리 기법을 다룹니다. 학습 순서는 1) YAML 설정을 통한 계층적 구조 이해, 2) Spring Profiles를 통한 환경별 분기 처리, 3) 외부 환경 변수를 이용한 민감 정보 보호 순으로 진행되며, 최종적으로 실제 운영 환경에 배포 가능한 수준의 설정 관리 전략을 완성합니다.

### 1️⃣ Spring Profiles
- 정의: 애플리케이션 실행 환경에 따라 서로 다른 설정을 적용하기 위한 논리적 단위입니다.
- 원리: `spring.profiles.active` 속성을 통해 특정 프로파일을 활성화하면, 해당 이름이 포함된 설정 파일(`application-{profile}.yml`)이 우선 적용됩니다.
- 예시: `application-dev.yml`과 `application-prod.yml`을 각각 분리하여 DB 접속 정보를 다르게 설정합니다.
- 주의사항: 활성화되지 않은 프로파일의 설정은 무시되므로, 필수 설정값은 `application.yml` 공통 파일에 두는 것이 안전합니다.
- 시험 포인트: 프로파일 활성화 방법(JVM 옵션, 환경 변수 등)과 우선순위.

### 2️⃣ YAML 설정 파일 (YAML Configuration)
- 정의: 기존 properties 파일보다 계층 구조 표현이 뛰어나고 가독성이 높은 설정 파일 형식입니다.
- 원리: 들여쓰기를 통한 계층적 데이터 표현으로, 불필요한 중복 키 값을 획기적으로 줄여줍니다.
- 예시: `spring: datasource: url: ...` 구조를 통해 깊은 계층을 한눈에 파악합니다.
- 주의사항: 탭(Tab) 문자를 사용하지 않고 반드시 공백(Space)으로 들여쓰기를 해야 합니다.
- 시험 포인트: YAML의 계층 구조와 계층별 값 정의 우선순위.

### 3️⃣ Environment 객체
- 정의: 스프링 부트에서 프로퍼티와 프로파일 정보를 추상화한 인터페이스입니다.
- 원리: 코드 내에서 직접 `Environment` 객체를 주입받아 현재 활성화된 프로파일이나 시스템 환경 변수를 조회합니다.
- 예시: `env.getProperty("database.url")`을 호출하여 설정 값을 동적으로 가져옵니다.
- 주의사항: 가급적 `@Value`나 `@ConfigurationProperties` 사용을 권장하며, 직접 주입은 최소화합니다.
- 시험 포인트: `getProperty` 메서드의 동작 방식 및 우선순위.

### 4️⃣ ConfigurationProperties
- 정의: 설정 파일의 값을 자바 객체로 타입 안전(Type-safe)하게 바인딩하는 기능입니다.
- 원리: `@ConfigurationProperties(prefix = "app.config")`를 사용하여 설정 파일의 값을 POJO 객체에 자동 매핑합니다.
- 예시: DB 설정값들을 `DatabaseConfig` 클래스로 객체화하여 사용합니다.
- 주의사항: 클래스에 Getter/Setter가 반드시 필요하며, 불변 객체를 위해 `@ConstructorBinding`을 권장합니다.
- 시험 포인트: `@Value`와 `@ConfigurationProperties`의 차이점.

### 5️⃣ 환경 변수 관리 (Environment Variables)
- 정의: OS 레벨에서 설정하는 키-값 쌍으로, 소스 코드에 민감 정보를 노출하지 않는 방식입니다.
- 원리: 시스템 환경 변수는 `application.yml`보다 높은 우선순위를 가지며, 자동으로 오버라이딩합니다.
- 예시: AWS_ACCESS_KEY나 DB_PASSWORD를 시스템 변수로 설정하여 배포 시 주입합니다.
- 주의사항: 로컬 개발 환경에서도 환경 변수 설정을 잊지 않도록 `run configuration`을 설정해야 합니다.
- 시험 포인트: 환경 변수가 설정 파일보다 우선 적용되는 이유.

### 6️⃣ 보안 설정 (Security Key Management)
- 정의: 데이터베이스 비밀번호, API 키 등 외부 노출 시 위험한 정보를 별도로 관리하는 전략입니다.
- 원리: 깃(Git) 등 형상 관리 도구에 포함되지 않도록 환경 변수나 별도의 Vault 시스템을 이용합니다.
- 예시: `.gitignore`에 설정 파일 내 민감 정보가 포함된 파일을 배제합니다.
- 주의사항: 환경 변수를 반드시 암호화하거나 접근 권한을 제한해야 합니다.
- 시험 포인트: 민감 정보를 소스코드에 커밋하지 않는 이유와 보안 원칙.

### 📊 비교 정리표
| 구분 | @Value | @ConfigurationProperties |
| :--- | :--- | :--- |
| 매핑 방식 | 개별 필드 주입 | 클래스 단위 객체 매핑 |
| 타입 안전성 | 낮음 (문자열 중심) | 높음 (객체 타입 검증) |
| 용도 | 간단한 개별 속성 주입 | 복잡한 설정 그룹 관리 |

| 구분 | application.yml | 환경 변수 (OS) |
| :--- | :--- | :--- |
| 보안성 | 낮음 (소스코드 노출 가능) | 높음 (런타임 주입) |
| 우선순위 | 낮음 | 매우 높음 |
| 관리 주체 | 개발자(코드) | 운영자(인프라) |

### 🧪 실전 시나리오
1. 로컬(Dev)에서는 H2 DB를 사용하고, 운영(Prod)에서는 MySQL을 사용하는 프로파일 분리 작업.
2. GitHub에 코드를 올릴 때 DB 비밀번호가 포함된 파일을 올리지 않도록 환경 변수(`DB_PASSWORD`)로 추출.
3. 운영 서버 배포 시 `java -jar -Dspring.profiles.active=prod ...` 명령어를 통해 실행 환경을 즉시 변경.

### 🚨 자주 하는 실수 TOP 6
1. YAML 파일에서 탭(Tab) 문자를 사용하여 파싱 에러 발생.
2. 프로파일 설정 파일명 오타(`application-prode.yml` 등).
3. 환경 변수를 OS에 설정했으나 애플리케이션을 재시작하지 않음.
4. `@ConfigurationProperties` 사용 시 빈(Bean) 등록 혹은 `@EnableConfigurationProperties` 누락.
5. 보안키를 소스 코드 내에 하드코딩하여 Git에 커밋하는 실책.
6. 로컬 환경에서 프로파일 활성화를 잊고 기본 프로파일로 DB 연동이 깨짐.

## 연습 퀴즈

1. 스프링 부트에서 설정 파일의 우선순위가 가장 높은 것은?
   A. application.yml
   B. application-dev.yml
   C. 시스템 환경 변수 (Environment Variables)
   D. @PropertySource 어노테이션
   정답: C
   관련 키워드: 우선순위
   해설: 스프링 부트 설정 우선순위에서 환경 변수는 파일 기반 설정보다 우선합니다. 따라서 운영 환경에서 파일 내 값을 덮어쓰기 위해 자주 사용됩니다.

2. YAML 파일 작성 시 주의사항으로 옳은 것은?
   A. 들여쓰기 시 Tab 문자를 사용해야 한다.
   B. 계층 구조는 반드시 공백(Space)으로 들여쓰기해야 한다.
   C. 주석을 사용할 수 없다.
   D. 데이터형은 반드시 명시해야 한다.
   정답: B
   관련 키워드: YAML
   해설: YAML 형식은 공백(Space)을 사용하여 계층을 표현하며, Tab 문자를 사용하면 파싱 에러가 발생합니다.

3. @ConfigurationProperties의 주요 장점은?
   A. 매우 짧은 코드로 단일 값을 주입한다.
   B. 타입 안전(Type-safe)한 설정을 객체로 관리할 수 있다.
   C. 가장 낮은 우선순위로 설정된다.
   D. 코드 실행 시점에 환경을 바꿀 수 없다.
   정답: B
   관련 키워드: ConfigurationProperties
   해설: 설정값을 POJO 객체로 바인딩함으로써 타입 체크가 가능하며, 관리 효율성과 가독성이 높아집니다.

4. 프로파일(Profile)을 사용하는 가장 주된 이유는?
   A. 자바 코드의 속도를 높이기 위해
   B. 운영체제를 변경하기 위해
   C. 개발, 테스트, 운영 환경별로 설정을 분리하기 위해
   D. 클래스 로딩 순서를 조정하기 위해
   정답: C
   관련 키워드: Spring Profiles
   해설: 환경마다 DB 주소, API 키 등 필요한 설정이 다르기 때문에 프로파일 기능을 통해 이를 분리하여 관리합니다.

5. 환경 변수를 통해 보안 정보를 관리하는 주된 이유는?
   A. 서버 성능을 향상시키기 위해
   B. 소스 코드 노출 시 보안 정보가 유출되는 것을 방지하기 위해
   C. 설정 파일을 생략하기 위해
   D. 환경 변수가 가장 빠르기 때문에
   정답: B
   관련 키워드: 보안 변수
   해설: 소스 코드가 Git 등에 노출되더라도 환경 변수에 저장된 민감 정보는 안전하게 보호됩니다.

## 주차 과제

제목: 환경별 프로파일 설정 실습

application.yml을 공통 설정으로 두고, application-dev.yml과 application-prod.yml을 생성하여 서로 다른 포트 번호를 적용해 봅니다.

[제출 체크리스트]
- application.yml에 공통 내용 작성 확인
- application-dev.yml 생성 및 server.port 설정
- application-prod.yml 생성 및 server.port 설정
- 실행 시 -Dspring.profiles.active 옵션 사용 결과 캡처

[필수 키워드] active profile, yaml 설정, server port, spring profiles

[수행 단계]
1. 1. application.yml 파일 수정 및 profile별 파일 생성
2. 2. 각 파일에 서로 다른 포트 번호 할당
3. 3. IDE 설정 또는 터미널 명령어를 통해 프로파일 전환 실행

[채점 기준] 요구된 3개의 설정 파일이 올바르게 작동하며, 실행 시 로그에서 프로파일 적용 여부가 확인되면 만점.
