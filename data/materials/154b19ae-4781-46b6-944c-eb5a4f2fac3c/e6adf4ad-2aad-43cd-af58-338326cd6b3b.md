## 마크다운 학습 자료

### 📌 이번 주차 전체 지도
1주차부터 9주차까지 학습한 Spring Boot의 핵심 개념(DI, MVC, JPA, Security, API 등)을 하나로 통합하여 소규모 웹 서비스를 완성합니다. 이번 주차는 개별적으로 학습했던 컴포넌트들이 어떻게 유기적으로 결합되어 하나의 시스템을 이루는지 확인하고, 로컬 환경을 벗어나 실제 배포(Deployment) 환경으로 서비스를 이전하는 과정을 다룹니다. 마지막으로 스프링 부트 생태계에서 실무자로 도약하기 위한 로드맵을 설계하며 전체 과정을 마무리합니다.

### 1️⃣ 빌드 자동화 (Build Automation)
- 정의: 소스 코드를 컴파일하고, 의존성을 해결하며, 실행 가능한 배포 파일(JAR)로 변환하는 자동화 과정.
- 원리: Gradle을 사용하여 프로젝트의 의존성을 관리하고 `jar` 태스크를 통해 배포 파일을 생성.
- 예시: `./gradlew build` 명령을 통해 build/libs 경로에 jar 생성.
- 주의사항: 로컬 환경과 배포 서버의 환경(JDK 버전 등)을 일치시켜야 함.
- 시험 포인트: `build.gradle`의 의존성 관리와 빌드 결과물의 위치 및 실행 명령어.

### 2️⃣ JAR 실행 및 환경 구성 (JAR Packaging)
- 정의: 웹 애플리케이션을 단독으로 실행 가능한 파일 형태로 만드는 것.
- 원리: 내장 톰캣(Embedded Tomcat)을 사용하여 별도의 WAS 설치 없이 자바 실행 명령어만으로 서버 가동.
- 예시: `java -jar my-app.jar --spring.profiles.active=prod`.
- 주의사항: 운영 환경(Production)의 데이터베이스 접속 정보는 반드시 환경 변수나 외부 설정 파일을 사용해야 함.
- 시험 포인트: 프로필(Profile) 전환을 통한 환경 설정 관리.

### 3️⃣ 배포 전략 (Deployment Strategy)
- 정의: 서비스가 운영 환경에서 사용자에게 접근 가능한 상태가 되도록 만드는 과정.
- 원리: 클라우드 서버(AWS EC2 등)에 애플리케이션을 복사하고 실행 권한을 부여하여 포트를 개방.
- 예시: SCP를 통한 파일 전송 후 서버에서 백그라운드 프로세스로 실행(`nohup`).
- 주의사항: 80번 포트 혹은 보안 그룹의 포트 포워딩(Port Forwarding) 정책 확인.
- 시험 포인트: 배포 자동화의 기본 개념과 런타임 환경 유지 방법.

### 4️⃣ CI/CD 기초 (Continuous Integration/Deployment)
- 정의: 코드 변경 사항을 자동으로 빌드하고 배포하는 지속적 통합/배포 프로세스.
- 원리: 코드 커밋 시 자동 빌드, 테스트를 거쳐 배포 서버로 자동 전송.
- 예시: GitHub Actions를 활용한 간단한 빌드 자동화 스크립트 작성.
- 주의사항: 테스트 케이스가 작성되어 있지 않으면 무분별한 배포가 발생함.
- 시험 포인트: CI와 CD의 차이점 및 장점.

### 5️⃣ 코드 리팩토링 (Refactoring)
- 정의: 외부 동작은 유지한 채 코드의 내부 구조를 개선하여 가독성과 유지보수성을 높이는 작업.
- 원리: 중복 제거, 명확한 네이밍, 객체지향 설계 원칙 적용.
- 예시: Controller에 집중된 로직을 Service 계층으로 이동.
- 주의사항: 리팩토링 중 기능을 추가하거나 수정하지 말 것.
- 시험 포인트: 리팩토링의 목적과 적절한 타이밍.

### 6️⃣ 스프링 학습 로드맵 (Learning Roadmap)
- 정의: 스프링 부트 입문 이후 실무자로 성장하기 위한 학습의 방향성.
- 원리: Spring Cloud, Spring Data JPA 심화, QueryDSL, MSA, Docker 학습.
- 예시: 3개월 단위로 심화 주제를 정해 토이 프로젝트 고도화.
- 주의사항: 모든 기술을 배우기보다 필요한 기술부터 깊게 파고드는 전략이 필요함.
- 시험 포인트: 실무에서 요구하는 스프링 부트의 핵심 요구 기술 스택.

### 📊 비교 정리표 1: 로컬 개발 환경 vs 운영 배포 환경
| 항목 | 로컬 개발 환경 (Local) | 운영 배포 환경 (Production) | 
| :--- | :--- | :--- | 
| DB 접속 | H2 내장 DB | 외부 상용 DB (MySQL/PostgreSQL) |
| 포트 설정 | 8080 | 80 또는 443 (Reverse Proxy 경유) |
| 로그 레벨 | DEBUG/INFO | WARN/ERROR |
| 배포 방식 | 즉시 실행 | 무중단 배포/자동 배포 |

### 📊 비교 정리표 2: 빌드 vs 배포 vs CI/CD
| 단계 | 수행 작업 | 주요 키워드 |
| :--- | :--- | :--- | 
| 빌드 | 컴파일 및 패키징 | Gradle, JAR, 의존성 |
| 배포 | 서버 전송 및 실행 | EC2, 포트, 환경변수 |
| CI/CD | 자동화된 빌드/배포 파이프라인 | GitHub Actions, 자동화 |

### 🧪 실전 시나리오
1. 배포 후 서버 접속 불가: 포트가 방화벽(Security Group)에서 열려 있는지, 앱이 올바른 포트에서 실행 중인지 확인.
2. 환경 변수 누락: DB 비밀번호 등이 소스 코드에 노출되지 않도록 `application-prod.yml`을 설정하고 실행 옵션으로 전달.
3. 무중단 배포 필요: 한 번에 서버를 끄지 않고 로드 밸런서를 사용하여 순차적으로 업데이트하는 전략 수립.

### 🚨 자주 하는 실수 TOP 6
1. 로컬 DB(H2) 설정을 그대로 배포하는 경우.
2. `.gitignore`에 환경 설정 파일을 포함하지 않아 보안 정보가 유출되는 경우.
3. 실행 중인 프로세스를 죽이지 않고 중복 실행하여 포트 충돌 발생.
4. 로그 파일을 확인하지 않아 배포 오류 원인을 찾지 못함.
5. 리팩토링을 기능 구현과 동시에 진행하여 시스템 전체 마비.
6. 서버 자원(Memory, CPU)을 고려하지 않은 무거운 빌드 수행.

### 💡 시험 포인트 & 암기 장치
- **B.D.D.** (Build -> Deploy -> Delivery): 배포 흐름 암기.
- **Profile 사용법:** `--spring.profiles.active` 명령어는 필수 암기.
- **JAR 실행:** `java -jar [파일이름].jar` (Spring Boot는 톰캣이 내장되어 있어 별도 설치 불필요).

## 연습 퀴즈

1. 스프링 부트 애플리케이션을 빌드하여 생성된 실행 가능한 파일 형식은 무엇인가?
   A. WAR
   B. JAR
   C. EAR
   D. EXE
   정답: B
   관련 키워드: Build
   해설: 스프링 부트는 내장 톰캣을 포함하며, 일반적으로 실행 가능한 JAR(Java Archive) 파일로 빌드하여 배포합니다.

2. 애플리케이션 실행 시 운영 환경 설정을 적용하는 올바른 커맨드라인 옵션은?
   A. --spring.profiles.active=prod
   B. -Dprofile=prod
   C. --mode=production
   D. -env=prod
   정답: A
   관련 키워드: Deployment
   해설: 스프링 부트는 `--spring.profiles.active`를 통해 실행 프로필을 동적으로 설정합니다.

3. CI/CD의 핵심 목적 중 하나가 아닌 것은?
   A. 배포 속도 향상
   B. 배포 안정성 확보
   C. 사람의 개입 최소화
   D. 코드의 모든 로직 삭제
   정답: D
   관련 키워드: CI/CD
   해설: CI/CD는 자동화를 통해 안정적이고 빠른 배포를 추구하며, 코드 삭제와는 관계가 없습니다.

4. 리팩토링(Refactoring)의 주된 목적은 무엇인가?
   A. 새로운 기능 추가
   B. 버그 수정
   C. 코드 가독성 및 유지보수성 향상
   D. 성능 100배 향상
   정답: C
   관련 키워드: Refactoring
   해설: 리팩토링은 외부 기능 변화 없이 내부 구조를 개선하여 유지보수성을 높이는 것이 핵심 목적입니다.

5. 배포 서버에서 JAR 파일을 실행할 때 가장 고려해야 할 사항은?
   A. 컴파일러 버전 일치
   B. 내장 톰캣 설치 여부
   C. 데이터베이스 접속 정보 및 포트 설정
   D. IDE 설치 여부
   정답: C
   관련 키워드: Deployment
   해설: 배포 환경에서는 로컬 DB가 아닌 운영 DB 연결 정보와 네트워크 포트 설정이 가장 중요합니다.

## 주차 과제

제목: 최종 프로젝트 배포 실습: 나만의 웹 서비스 띄우기

학기 중 작성한 스프링 부트 프로젝트를 빌드하고, 로컬이나 가상 서버(또는 클라우드 무료 티어)에 직접 배포하여 외부에서 접속 가능하도록 만드는 실습입니다.

[제출 체크리스트]
- 프로젝트 루트에서 ./gradlew build 완료 확인
- 빌드된 JAR 파일을 실행하여 서버 정상 구동 확인
- application-prod.yml 파일 작성 및 환경변수 반영
- 포트 8080 또는 80을 통해 웹페이지 접속 성공 캡처

[필수 키워드] JAR, Build, Profile, Deployment

[수행 단계]
1. 1. 코드 클린업 및 설정 파일(prod) 작성
2. 2. Gradle을 이용한 실행 파일(JAR) 빌드
3. 3. 서버 환경에서 java -jar 명령어로 애플리케이션 실행

[채점 기준] 정상 빌드 여부(40점) + 운영 환경 설정 적용(30점) + 외부 접속 확인(30점)
[배점] 100점
